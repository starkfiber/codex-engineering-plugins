# Apple / Reverse Lab / RF² / RUOS handoff

Apple owns SDK, signing, native interaction and physical-device acceptance. Reverse Lab can explain authorised shipped artifacts: record SHA-256, architecture, tool and observation; distinguish static inference from runtime evidence. Never patch store binaries or bypass protections as a default testing route.

RF²: request current status before planning execution, then check profiles, target and effects. A macOS ARM64 runtime does not prove iOS signing, sandbox, ABI or device support. Treat RF² as an optional checked-computation boundary; use synthetic/non-sensitive inputs and explicit output contracts. Compilation is not device acceptance. Keep provider secrets, credentials, customer data and signing keys out of shared jobs.

RUOS is a separate architecture and OS. An ARMv7 target cannot directly consume an ARM64 runtime. Transfer acceptance methods (identity, bounded diagnostics, replay protection, frame measurement), not Apple SDK assumptions or unqualified driver compatibility. Respect the target project's active device lease and rollback plan. No flashing, port takeover or interference with another agent's test run is implied by a documentation handoff.

Keep continuity in project-owned local files. Cross-project reference learning does not authorise uploading source or identifiers to shared corporate memory.
